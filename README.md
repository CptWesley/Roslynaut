# Roslynaut

An MCP server that gives coding agents what an IDE knows about C# code. It loads your solution with Roslyn and MSBuild, so an agent can navigate by symbol, refactor, build and test, read IL, JIT output and decompiled code, inspect and trace running processes, and debug, instead of reading and grepping files.

## Requirements

- The .NET 10 runtime or later, to run the tool. Installing it with `dotnet tool install` or running it with `dnx` takes the .NET 10 SDK or later.
- The .NET SDK your projects build with, as their `global.json` picks it. Roslynaut loads projects through MSBuild design-time builds, and it does not need to be the SDK of the runtime that runs the tool.
- Roslynaut reads code with its own bundled Roslyn version (5.12), which knows C# up to the version the .NET 11 SDK builds. A project on a newer SDK loads without the language version and analyzers that compiler lacks, and `diagnostics` reports them as warnings CS1617 and CS9057: update Roslynaut to read it fully.
- For the debug tools, [netcoredbg](https://github.com/Samsung/netcoredbg), on the `PATH` or at the path in `NETCOREDBG`.

## Install

```sh
dotnet tool install -g Roslynaut
roslynaut --install claude    # or: opencode, codex, vscode, visualstudio, copilot, cursor, gemini, junie
```

### Without installing, through `dnx`

If `dotnet tool install -g` fails, for example because you lack permission to write to the global tools directory, run Roslynaut through `dnx` (.NET 10 SDK), which downloads the package into your NuGet packages folder and runs it from there:

```sh
dnx Roslynaut@1.2.3 --yes --install claude    # or any other agent
```

Give a fixed version, the latest of which you find on [nuget.org](https://www.nuget.org/packages/Roslynaut/) (the badge above), or with:

```sh
dotnet package search Roslynaut --exact-match    # every version; add --prerelease for previews
```

`--install` registers `dotnet dnx Roslynaut@<version> --yes`, so the agent starts that version until you install another. Clearing the NuGet packages folder, as `dotnet nuget locals all --clear` does, only makes dnx download it again when the agent next starts it. To upgrade, run it with the new version. To uninstall, run `dnx Roslynaut@<version> --yes --uninstall claude`.

### Claude Code

`--install claude` registers Roslynaut with Claude Code for all your projects, as the user-scope MCP server `roslynaut` in `~/.claude.json`. It also adds hooks to `~/.claude/settings.json`. They suggest Roslynaut's tools for the job, along with the solution to pass them: when a session starts (or resumes, or is compacted) in a C# repository, when Claude reads, finds or greps C# files, after it edits one, and when it runs `dotnet build` or `dotnet test`. The hooks only add that suggestion: they never block or approve a tool call. Both files go under `CLAUDE_CONFIG_DIR` when that is set. Restart Claude Code afterwards. `dotnet tool update -g Roslynaut` keeps the registration, as the command stays the same.

### OpenCode

`--install opencode` registers Roslynaut with OpenCode for all your projects, as the MCP server `roslynaut` in the global `opencode.json(c)` (under `~/.config/opencode`, or `XDG_CONFIG_HOME` when that is set). It also adds a plugin to `~/.config/opencode/plugins/roslynaut.js`. When OpenCode reads or greps C# files, the plugin appends the same suggestion to the tool result. The plugin only adds that suggestion: it never blocks or approves a tool call. OpenCode reloads its configuration and plugins without a restart.

### Other supported MCP clients

The other agents get the MCP server `roslynaut`, for all your projects, in their user configuration, without a hook: the server instructions tell the agent which tool to use for what.

| Agent | Configuration |
|---|---|
| `codex` (Codex CLI, IDE extension and app) | `[mcp_servers.roslynaut]` in `~/.codex/config.toml` (under `CODEX_HOME` when that is set), with a tool timeout of 30 minutes for builds and tests |
| `vscode` | `servers` in the user profile's `mcp.json`: `%APPDATA%\Code\User` on Windows, `~/Library/Application Support/Code/User` on macOS, `~/.config/Code/User` on Linux. The default profile of VS Code stable only; for Insiders or another profile, add the same entry through **MCP: Open User Configuration** |
| `visualstudio` | `servers` in `%USERPROFILE%\.mcp.json` |
| `copilot` (GitHub Copilot CLI) | `mcpServers` in `~/.copilot/mcp-config.json` (under `COPILOT_HOME` when that is set), with all its tools |
| `cursor` | `mcpServers` in `~/.cursor/mcp.json` |
| `gemini` (Gemini CLI) | `mcpServers` in `~/.gemini/settings.json` |
| `junie` (Junie in JetBrains IDEs, and its CLI) | `mcpServers` in `~/.junie/mcp/mcp.json` |

### Other Unsupported MCP clients

Run the command `roslynaut`, which serves MCP over stdio. For example, for one VS Code workspace, in its `.vscode/mcp.json`:

```json
{
  "servers": {
    "roslynaut": { "type": "stdio", "command": "roslynaut" }
  }
}
```

`roslynaut --protocol http` serves streamable HTTP at `http://localhost:5000/`, and `--protocol sse` serves legacy SSE at `http://localhost:5000/sse`. Set `ASPNETCORE_URLS` to listen elsewhere. The server only answers requests addressed to `localhost`, `127.0.0.1` or `[::1]`; to serve another host name, set `AllowedHosts` to it. The HTTP server has no authentication.

## Usage

Most tools take `projectPath`, the path of a `.csproj`, `.sln` or `.slnx`. Roslynaut loads it on first use and keeps it in sync with the files on disk. Tools that work on a symbol take either a symbol path, such as `MyApp.Orders.OrderService.Submit(int)`, or a `filePath` with a 1-based `line` and `column`.

The server tells agents which tool to use for what, so an agent picks them up without further instructions.

On Linux, each loaded project or solution watches its files through a few inotify instances, and many distributions allow 128 per user, for all programs together. If tools fail with "The configured user limit (128) on the number of inotify instances has been reached", raise the limit: `sudo sysctl fs.inotify.max_user_instances=1024`.

## Tools

- **Navigation**: `definition`, `references`, `implementations`, `callers`, `callees`, `call_paths`, `type_hierarchy`, `document_symbols`, `list_symbols`, `find_symbols`, `workspace_symbols`, `symbol_source`, `document_highlight`, `search_pattern`, `find_operations`, `generated_sources`
- **Code analysis**: `diagnostics`, `expression_info`, `signature_help`, `completion`, `inlay_hints`, `syntax_tree`, `control_flow`, `data_flow`, `throws`, `code_metrics`, `find_duplicates`, `unused_symbols`, `public_api`, `api_diff`, `namespace_graph`, `di_registrations`, `aspnet_endpoints`, `resources`, `regex_test`
- **Code actions and refactoring**: `code_actions`, `apply_code_action`, `fix_all`, `format`, `organize_usings`, `rename_symbol`, `change_signature`, `extract_interface`, `move_to_namespace`, `safe_delete_symbol`
- **Symbol edits**: `replace_symbol_body`, `insert_before_symbol`, `insert_after_symbol`, `preview_edit`
- **Projects and MSBuild**: `project_graph`, `project_info`, `workspace_options`, `msbuild_evaluate`, `msbuild_property_trace`
- **Builds and binary logs**: `build`, `build_problems`, `build_diff`, `build_file_origin`, `build_incrementality`, `build_log_search`, `build_property_trace`, `build_target_why`
- **Tests**: `find_tests`, `run_tests` (also mutation testing with Stryker.NET), `affected_tests`, `verify_pending`
- **NuGet packages**: `packages`, `package_info`, `package_search`, `package_why`, `package_upgrade_check`, `package_licenses`, `package_contents`, `package_assembly`, `nuget_config`
- **IL, JIT and decompilation**: `symbol_il`, `symbol_asm`, `assembly_il`, `assembly_asm`, `type_layout`, `decompile`, `assembly_sources`, `resolve_stack_trace`
- **Running code**: `evaluate`, `benchmark` (off by default, see below)
- **Processes and dumps**: `dotnet_processes`, `process_threads`, `process_heap`, `process_objects`, `process_roots`, `process_async`, `process_dump`, `process_cpu`, `process_allocations`, `process_counters`, `process_events`, `process_calls`
- **Debugging**: `debug_start`, `debug_attach`, `debug_test`, `debug_breakpoints`, `debug_inspect`, `debug_set`, `debug_resume`, `debug_stop`
- **The tools themselves**: `explain_tool` (their descriptions, for a server started without them)

## Options

| Option | Effect |
| --- | --- |
| `--protocol stdio\|http\|sse` | The transport. The default is `stdio`. |
| `--enable-tools <tool>...` | Serve only these tools. With `--install`, the agent starts the server with them. |
| `--disable-tools <tool>...` | Leave these tools out. With `--install`, the agent starts the server without them. |
| `--no-instructions` | Leave out the server instructions that tell agents which tool to use for what. |
| `--no-tool-descriptions` | Leave the tools' descriptions out of their schemas (30% of them); agents get them from `explain_tool`. With `--install`, the agent starts the server so. |
| `--no-field-descriptions` | Leave the parameters' descriptions out of the tools' schemas (43% of them); agents get them from `explain_tool`. With `--install`, the agent starts the server so. |
| `--install <agent>` | Register with an agent (`claude`, `opencode`, `codex`, `vscode`, `visualstudio`, `copilot`, `cursor`, `gemini`, `junie`), then exit. |
| `--no-hooks` | With `--install`, register the server alone: Claude Code gets no hooks and OpenCode no plugin, and those of an earlier installation are removed. |
| `--uninstall <agent>` | Remove that registration, then exit. |

| Environment variable | Effect |
| --- | --- |
| `ROSLYNAUT_ALLOW_EVALUATE=true` | Serves `evaluate` and `benchmark`, which run arbitrary code. |
| `NETCOREDBG` | The path of netcoredbg, for the debug tools, which the server leaves out when it finds netcoredbg neither here nor on the `PATH`. |
| `_NT_SYMBOL_PATH` | Symbol servers and directories to find PDBs in, before the Microsoft and NuGet symbol servers. |
| `ASPNETCORE_URLS`, `AllowedHosts` | Where the HTTP server listens, and the host names it answers to. |

## Security

Use Roslynaut on code you trust, as you would `dotnet build`:

- Loading a project runs its MSBuild targets, and loads its analyzers and source generators into the server.
- `build`, `run_tests`, the debug tools and the process tools that launch a program run the project's code.
- `evaluate` and `benchmark` run code that the agent writes. The server leaves them out unless `ROSLYNAUT_ALLOW_EVALUATE=true`.
- Over HTTP, anyone who can reach the port can use all of this.

Some tools download:

- packages from your NuGet feeds, with the credentials of your `nuget.config` or credential providers;
- PDBs from symbol servers, and source files through SourceLink;
- Stryker.NET, for `run_tests` with mutation testing;
- BenchmarkDotNet, for `benchmark`.

## Uninstall

```sh
roslynaut --uninstall claude    # and every other agent you installed for
dotnet tool uninstall -g Roslynaut
```

Run `--uninstall` first, for every agent you installed for. It removes the server and its hook or plugin. Once the tool is gone, Claude Code and OpenCode could no longer start the hook or plugin.
